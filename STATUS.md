# STATUS — Nurse Preceptor Toolkit

## What was built

An education-only manual (never medical advice) for nurses asked to precept, delivered two ways:

- **Markdown source** — `docs/` (11 chapters) and `worksheets/` (6 printable sheets)
- **Static HTML site** — generated by `build.py` into `site/` (19 pages), stdlib-only, offline, zero dependencies

### Chapters (docs/)

1. Read this first — scope, disclaimers, ground rules, related projects
2. Setting a new grad at ease — four day-one scripts, first-week shape table, week-one recap script, ease habits
3. Teaching without rescuing — the five-rung autonomy ladder, three handing-over sentences, four step-in reasons, rescue audit, debrief habit
4. Feedback delivered kindly — bar/gap/next-attempt shape, moment rules table, copyable openers for hard feedback, teaching the receiving half, formative-vs-formal boundary
5. Growing critical thinking — six-rung question ladder, three anchor questions, role-play drills, freeze protocol, thirteen-question starter bank
6. Using AI for lesson plans — four safety rules (no patient data; AI drafts/humans author; no confidential text; workplace policy), six-step verify workflow with `[VERIFY]` convention, strength/limitation table, failure modes, time budget
7. Dry-run scenarios — build-and-verify loop with `[PRECEPTOR FILLS]` convention, six scenario shapes (all fact-free), orientee pushback handling
8. Documenting precepting hours — three-tier system, independence vocabulary (watched/side-by-side/checked/independent), ten-line weekly summary, privacy fence, hours-vs-readiness disagreement handling
9. Surviving the difficult week — five rough shapes with first moves, tears protocol, momentum rebuild, preceptor floor care, pre-Friday script, weather-vs-signal escalation
10. Handoff readiness summary — final-week shape, two-half summary format, Thursday conversation, honest farewell, educator handoff paragraph
11. Glossary — role/program, coaching-method, document, and caution words, translated

### Worksheets (worksheets/)

- `preceptor-setup.md` — fill-once week-one launchpad
- `weekly-teaching-plan.md` — the reusable weekly plan with AI-verification and rescue-audit sections
- `role-play-question-bank.md` — question bank, drill log, freeze log
- `precept-hours-log.md` — three-tier hours/skills/milestones log (initials-only, facility-forms-first)
- `hard-week-onepager.md` — difficult-week triage kit
- `readiness-summary.md` — one-page end-of-precepting handoff form

### Site generator (build.py)

- Minimal markdown renderer (headings, tables, nested lists, checkboxes, blockquotes, fenced code, inline bold/italic/code/links)
- Warm print design; print styles for worksheets; strict CSP (`default-src 'none'`) on every page
- Education-only banner + "not medical advice" + LLC copyright footer on every generated page
- Prev/next navigation chains for chapters and worksheets
- Source validation (`--check-only`): disclaimers AND exact banner line present, titles present, minimum counts (11 chapters / 6 worksheets), internal link targets resolve
- Post-build validation: every href in every generated page must exist inside the site tree

## How to run

```bash
python3 build.py                           # build into site/ + validate links
python3 build.py --check-only              # validate sources only
python3 -m unittest discover -s tests -v   # run the 29-test suite
```

Then open `site/index.html` in any browser — no server, no network, no analytics. (`python3 -m http.server --directory site` works too if you prefer a local server.)

## Known gaps / honest limits

- The markdown renderer covers the constructs used by these docs (no images, footnotes, or nested tables). Unsupported syntax renders as plain paragraphs rather than erroring.
- The autonomy rungs, ladder, and difficult-week shapes are experience-based coaching conventions, not research citations; the guide deliberately points to facility process and educators for anything formal.
- AI prompt templates are written tool-agnostically and untested against any live model by design — the whole workflow assumes the human verifies, and the [VERIFY]/[PRECEPTOR FILLS] conventions are manual habits, not enforced by software.
- Site styling is embedded inline per page (plus a copyable `style.css`) so the site works from any folder without a server; some CSS duplication could be refactored later.
- No search feature; the index is the search at this size.
- External link: dylanasdale.github.io hub appears only in README; everything else is internal or sibling-project names.
- The guide is education-only by design: it deliberately does not reproduce or summarize any clinical procedure, and never will.
